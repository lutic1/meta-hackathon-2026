# Adversary review: two units that obey every AD and still do not fit

## Method

For each pair below, two packages one level under the spine are each built by an owner who reads the spine, `SPEC.md`, its companions, and `schema-v1.md`, and follows every AD to the letter. Each owner's choice is defensible from the text. The pair is then assembled. Where the result is a room that does not build, a lock that does not open, a counter that lies, or a replay that differs from live, the spine has a hole, and the fix is AD text, a convention row, or a Deferred entry. Ten pairs were constructed; all ten assemble incompatibly. Four are critical (a judge or the playtester would see the failure), five high, one medium.

Inputs: the spine (all sections); `SPEC.md`, `stack.md`, `budgets.md`, `player-profile.md`, `delivery-plan.md`, `glossary.md`; `schema-v1.md`. Overlaps with the rubric review in this folder are cross-referenced so fixes land once.

## Verdict

**Revise.** The spine fixes packages, ports by name, the solution boundary, the write gate, and the two clocks, and it does so tightly enough that the pairs below are not about those. They are about the seams the spine leaves to whoever arrives first: who mints an id and in which pixel space, who stamps time on an event, who assembles an `order` input, whether a retry can be served the response that failed, whether a counter shared by twenty concurrent inputs can be trusted, what a room version is and how a running session points at one, what shape the `derived` block has and who clamps it, and which flag picks the Guide. Each is closed by a paragraph of AD text; none needs a new package or a paradigm change.

## Pairs

### P-1 (critical) — Who assigns interactable ids, and in which pixel space the mask lives

- **Units:** `src/pipeline` (segment stage) and `src/council` (`architect.py`, `riddler.py`).
- **Pipeline may legally:** mint `ix_` ULIDs when it assembles `Interactable`s from the Architect's boxes and the SAM masks (Conventions, Ids). Store `mask` as a polygon "in image pixel space" (Conventions, Time and formats) and, having the original on disk for Tier 2, choose the original's pixel space. Keep `box` on the 0 to 1000 grid as `schema-v1.md` describes it ("from the vision call").
- **Council may legally:** realize AD-2 by using the `Interactable` pydantic model as the Architect's `response_schema`, so the model returns `id` values (`ix_lamp`, `ix_books`) that the Riddler prompt later cites, because the Riddler is "typed on `RoomView`" and `RoomView` carries whatever ids the room has. Parse the Riddler's `solution` and `evidence.interactable` back by label when the model drifts, since nothing forbids it.
- **Incompatibility:** every interactable has two ids, the model's and the pipeline's; `Puzzle.solution` and `evidence.interactable` reference the model's; validator rule 3 fails every room (or passes only because the council re-maps by label, which breaks the moment two interactables share a label such as grouped "books"). Independently, the client renders hotspots on the 1280 px texture while the polygon is in original pixels (or `box` is on a 0 to 1000 grid next to a `mask` in pixels), so hotspots land off the object. The capture proof's T1 ("first hotspot responding") is the first thing a judge sees.
- **Closing AD text (new AD-18, Interactable identity and image space; Binds CAP-1, CAP-2, CAP-3, CAP-11; Prevents two ids or two coordinate spaces for one object):** "`ix_` ids are minted only by the pipeline segment stage, after mask selection and the 12-cap, and never appear in or come from a model response. The Architect response is a separate `ArchitectResponse` model in `src/domain/schema.py` (`objects[]` of `label`, `photo`, `box`, `attributes[]`, `confidence`), correlated to interactables by list position. Every council prompt that names an object renders both `id` and `label` from the `RoomView`, and model output is parsed back to interactables by exact `id` match, never by label. `box` is converted from the 0 to 1000 grid to pixels at segment time and stored only in pixels. `box` and `mask` are in the pixel space of the stored downscaled JPEG (`photos[i].downscaled`); the client renders hotspots on that file at its natural size; `tier2` is the only field that may reference original-resolution pixels. `Interactable.photo` is an index into `photos[]`, which is in upload order."

### P-2 (high) — Which bytes are "the downscaled image"

- **Units:** `web/` (capture wizard) and `src/pipeline` (ingest stage).
- **Web may legally:** downscale in a Canvas to 1280 px, as `stack.md` says ("Canvas downscale to 1280 px; originals kept"), and upload both files. Chrome applies EXIF orientation when drawing a file into a Canvas, so the client's JPEG is upright.
- **Pipeline may legally:** read AD-7 ("stores photos") and the Conventions row ("images stored as the downscaled 1280 px JPEG plus the original") and produce the downscaled JPEG itself with Pillow from the original, since nothing says the client did it. Pillow does not apply EXIF orientation unless asked, so a portrait phone photo is stored rotated.
- **Incompatibility:** two different 1280 px images exist for one photo. SAM segments the server's (rotated) one; the scene renders the client's (upright) one from memory; every polygon is rotated 90 degrees. Even without rotation, two encoders give two byte streams, so the cache key (AD-6, `sha256(downscaled image bytes)`) differs between a local build and a hosted build of the same photos, and the "identical image-hash" promise of CAP-9 holds only by accident. `photos[].hash` is defined on neither.
- **Closing AD text (amend AD-7 and the Time and formats row):** "The browser produces the downscaled JPEG (Canvas, EXIF orientation applied, long edge 1280, quality 0.85) and uploads it with the original in one multipart request; the ingest stage stores both byte for byte and re-encodes neither; it rejects (422) a downscaled file whose long edge is not 1280 or that carries an orientation tag other than 1; `photos[i].hash` is sha256 of the stored downscaled bytes; every model call, cache key, and mask uses those bytes; the scene renders `GET /rooms/{id}/photos/{i}` (the stored file), never an in-memory canvas." If the server is preferred as the single encoder instead, the rule must say so and require `ImageOps.exif_transpose`; either is fine, the spine must pick one.

### P-3 (critical) — Who produces `idle_tick`, who stamps time, and where `DEMO_TIMESCALE` is applied

- **Units:** `web/` (play client) and `src/domain/session.py` with the `api` session routes.
- **Web may legally:** post `idle_tick` events itself, since AD-4 says the client "posts events" and `idle_tick` is in the list; stamp them with its own clock; read `DEMO_TIMESCALE` from `GET /meta` (AD-15 exposes "flags") and, understanding demo mode as "the game runs at a compressed timescale" (CAP-8), post ticks six times as often.
- **Session may legally:** keep `src/domain` pure (AD-1: no clock), so time can only arrive on events, and trust the client's timestamps; apply `DEMO_TIMESCALE` in the session clock by dividing the nudge threshold by six (AD-10). Or, equally legally, generate `idle_tick` server side from the `Clock` port and ignore client ticks.
- **Incompatibility:** three distinct failures. (a) Both sides apply the timescale: the client ticks 6x faster and the server divides the threshold by 6, so at `DEMO_TIMESCALE=6` the nudge fires after 2.5 real seconds, and the CAP-8 proof ("three rungs inside 40 s") is wrong by a factor of six in either direction depending on which owner won. (b) Neither produces ticks because each assumed the other did: nudges fire only on wrong attempts and the playtest's idle path (CAP-4) never escalates. (c) The client stamps time, so the "just tell me the answer" attack is a `curl` posting one `idle_tick` with `t_ms` two hours ahead; three rungs unlock at once; CAP-3's attack success criterion fails while AD-4 is obeyed to the letter. A fourth, quieter failure: if `apply` reads `Clock.now()` anywhere, replaying the log (AD-4, "state is replayed from events") produces different rung changes than live.
- **Closing AD text (amend AD-4 and AD-10):** "Every event carries `t_ms`, session-clock milliseconds since session start, stamped by the API from the session `Clock` at receipt; a client-supplied timestamp is rejected (422). The client posts only `click`, `lock_input`, and `hint_request`. `idle_tick` is appended by the API on each `GET /sessions/{id}` read when at least 5000 ms have passed since the last event (no background ticker, so hosted containers need none); the client polls every 2000 ms. `DEMO_TIMESCALE` is applied in exactly one place, `domain/clock.py`'s session clock, which divides the nudge threshold, rung spacing, and Trickster window; `t_ms` and the tick cadence are real time, and the client never reads `DEMO_TIMESCALE` for any timing. Rung selection is the pure function `select_rung(events, derived, thresholds)` in `domain/rungs.py`, evaluated inside `apply`, and a `rung_change` is appended to the log with the ids of its triggering events, so a replay yields the same rung changes as live."

### P-4 (high) — Who assembles an `order` input, and what counts as a wrong attempt

- **Units:** `web/scene` and `src/domain/session.py`.
- **Web may legally:** read `schema-v1.md` ("`order` is the sequence of hotspot clicks since the last wrong attempt") as a client-side buffer, and post one `lock_input{puzzle_id, input: [ix_a, ix_b, ix_c]}` when the buffer reaches the solution length; post `find` as `lock_input{input: ix_id}`; post `click` only for hotspots that are not locks (AD-11: "the client sends interactable ids and lock inputs").
- **Session may legally:** evaluate `order` and `find` from `click` events alone, because the sequence "since the last wrong attempt" is server state (the server knows when the last wrong attempt was, the client only guesses), and ignore `lock_input` for those lock types; count every click that does not advance a puzzle as a wrong attempt.
- **Incompatibility:** the client posts `lock_input` for `order`, the server waits for `click`s that never come (or arrive without the ones the client swallowed as "lock" clicks); `order` and `find` puzzles never open. If both paths are implemented, a lock evaluates twice. Separately, if exploratory clicks count as wrong attempts, the 3-wrong-attempts nudge fires on a player looking around, and `wrong_attempts` in the room result (and so `persistence` in P-8) is noise.
- **Closing AD text (amend AD-4):** "Event payloads are pydantic models in `src/domain/schema.py`: `ClickEvent{interactable_id}`, `LockInputEvent{puzzle_id, input}` where `input` is `CodeInput | UseOnInput` only, `HintRequestEvent{puzzle_id}`, `IdleTickEvent{}`, `TricksterCardEvent{edit_id, accepted, room_version}`, `RungChangeEvent{puzzle_id, rung, triggered_by[]}`. The client posts a `click` for every hotspot click and a `lock_input` only for `code` (on submit) and `use_on` (on drop). `apply` evaluates `order` from the buffer of clicks since the last failed evaluation, compared when it reaches the solution length, and `find` from a click whose `interactable_id` is the solution of an available `find` puzzle (all `requires` open, not solved); the client never posts `lock_input` for `order` or `find`. A wrong attempt is counted only on a failed `code` or `use_on` input or a failed completed `order` buffer, never on a click."

### P-5 (high) — The cache key against the regeneration loop, and the guard against the cache

- **Units:** `src/providers` (`cache.py`, `spend.py`) and `src/pipeline` (`regenerate.py`).
- **Providers may legally:** key on exactly what AD-6 lists (image bytes, prompt, model id, schema hash), so `temperature`, `reasoning_effort`, seed and attempt number are not in the key; run `guard` before `get_or_call` in that order, as AD-6 states, so a cache hit is still priced and can be refused.
- **Pipeline may legally:** implement the "regeneration loop (at most 2)" of AD-13 as re-issuing the Riddler call with the same prompt and a higher temperature when the failure was a dry-run mismatch rather than a validator rule (the failure list of `schema-v1.md` is only specified for the Riddler prompt, and an owner may append it to the system message, which a providers owner may exclude from "prompt" when hashing); re-run the dry run after a regeneration that changed nothing textual.
- **Incompatibility:** with `CACHE=on` (the default, and what every agent dev loop runs) the regeneration is served the exact response that just failed, twice, in under a second, and the capture screen asks for re-capture: CAP-2's "within 2 regenerations" is defeated deterministically rather than probabilistically. In play, two Trickster windows with the same game-state summary return the same cached proposal, so the live Trickster looks scripted. And because the guard precedes the cache, a cache hit at the spend cap is refused, so the cheapest possible call (free) is the one the cap blocks; after Thu Nov 5 at the $25 cap, a judge re-running the demo photos hits a refusal on a $0 call.
- **Closing AD text (amend AD-6):** "`key = sha256(model id ‖ schema hash ‖ full prompt including system message ‖ reasoning_effort ‖ sha256 of each image in request order ‖ attempt)`; `attempt` is an integer the caller passes, default 0; `src/pipeline/regenerate.py` passes `attempt = regeneration count` on every Riddler and dry run call and `council/trickster.py` passes the window index, so a retry is never served the response that failed; text-only calls omit the image segment. `Cache.get_or_call` is consulted before `SpendLedger.guard`; a hit is never priced or refused; the guard runs only on a miss. The mock provider bypasses both." (Rubric review R-7 names the text-only key gap; this closes it and the attempt gap together.)

### P-6 (high) — Ledger persistence and concurrency under `@modal.concurrent(max_inputs=20)`

- **Units:** `src/providers/spend.py` and `src/infra` (`local.py`, `modal.py`).
- **Providers may legally:** persist the counter "through `JobStore`" (AD-6) as a read-modify-write of one key: `total = store.get("ledger"); store.put("ledger", total + cost)`; hold the "last observed cost per kind" estimate (`budgets.md`) in a module variable.
- **Infra may legally:** type `JobStore` around jobs (`get(job_id) -> Job`, `put(job)`), so a `ledger` key is either a type error or a special case; implement hosted `JobStore` as `modal.Dict` (Structural Seed) while `budgets.md` says the counter lives "on the Volume", so a second owner reading budgets writes it to the Volume; provide no lock because the port names none.
- **Incompatibility:** twelve parallel SAM calls per build (`budgets.md`, "In parallel") times up to twenty concurrent inputs per container do read-modify-write on one key with no atomic increment (`modal.Dict` has none); the counter under-counts by whatever interleaves, and the local JSON `JobStore` corrupts under concurrent writes. The per-kind estimate differs per container, so the pre-call refusal differs per container. If providers write the Dict and infra reads the Volume, "the counter survives restarts" (CAP-9) is true of a number nobody reads. The $80 cap is the one hard money constraint of the project and it is enforced by a race.
- **Closing AD text (amend AD-6 and AD-9):** "The ledger has its own port, `LedgerStore` in `pipeline/ports.py`: `append(entry: SpendEntry)` and `entries()`, append-only, one entry per priced call keyed by a `call_` ULID; local mode appends one JSON line to `.cache/ledger.jsonl` under a file lock; hosted mode writes one `modal.Dict` key per entry and sums on read; the Volume holds no ledger. `guard` appends a `reserved` entry with the estimate before the call and replaces it with the observed cost after, so in-flight calls count toward the cap; one `SpendLedger` instance per process serializes `guard` with a lock; the per-kind estimate is read from the last observed entry of that kind in the store, not from memory. Hosted mode sets `max_containers=1` in `modal_app.py` (twenty own-room builds need no more), so the process lock is the global lock; raising it requires a store with atomic increment and is Deferred." Also add `LedgerStore` to the list of adapters `MODE` selects in AD-9.

### P-7 (critical) — What a Room version is, and how a running session points at one

- **Units:** `src/council/trickster.py` with the `api` session routes, and `src/pipeline` (`ArtifactStore`, the "pipeline stage runner" as a writer).
- **Council and api may legally:** make "a new Room version" (AD-12) a new `room_` ULID with the parent in `provenance` (schema v1 has no `version` field, and ids are ULIDs by convention); or, equally legally, keep the id and bump an integer they add. Have the session route write the new room, because somebody must and the Trickster runs during play, not in a pipeline stage.
- **Pipeline may legally:** read the State mutation row ("`SessionStateMachine.apply` and the pipeline stage runner are the only writers") and reject any `ArtifactStore.put_room` call from `api` in review; key `ArtifactStore` by `room_id` so a same-id version overwrites the file, which is an in-place mutation at the storage layer while AD-12 is obeyed at the object layer.
- **Incompatibility:** under the new-ULID reading, `Session.room_id` still names the pre-edit room: the client keeps rendering the old `requires` graph while `apply` evaluates against the new one, so a `merge` edit leaves a lock the client shows as available that the server refuses, which on video reads as a broken game. Under the same-id reading, the rejected card "references the unchanged version" of a file that has just been overwritten by the previous accepted edit. In both readings, replay cannot reproduce live because the log's `trickster_card` event does not say which room version was active for the events after it. And by the letter of the conventions, nobody is allowed to write the version at all.
- **Closing AD text (amend AD-12 and the State mutation row):** "`Room.id` is stable across versions; `Room.version` (int, 1 at build) and `Room.edits[]` (accepted `TricksterEdit`s in order) are schema fields. `ArtifactStore` stores `rooms/<room_id>/v<version>.json` and refuses to overwrite an existing path. `council/trickster.py` exposes the pure `apply_edit(room, edit) -> Room` (version + 1); the api session route is the named third writer: it calls `validate` on the result and, on pass, `ArtifactStore.put_room`. The log's `trickster_card` event carries `{edit_id, accepted, room_version}`, where `room_version` is the version in force after the event (unchanged on reject). `SessionStateMachine.apply` evaluates every event against the version named by the last `trickster_card` before it (`Session.room_version`, 1 at start), which is what makes replay deterministic. `GET /sessions/{id}` returns `room_version`; the client refetches `GET /rooms/{id}?version=n` when it changes and never caches a room across versions." (Rubric review R-1 covers the purity half of AD-12; this covers the versioning half.)

### P-8 (high) — The `derived` block's shape and clamping against the rung thresholds

- **Units:** `web/profile` and `src/domain/rungs.py`.
- **Web may legally:** compute `derived` in the browser (it owns `ROOM_RESULT` and `DERIVED`, AD-8 and the ER diagram), hand-write its TypeScript type because `Derived` is not in Schema v1 and so not in `GET /schema` (AD-2's generated-types rule covers Schema v1), send `persistence` unclamped as computed (a player who idled through every nudge yields 1.8), send `time_to_first_hint` in session-clock milliseconds (Conventions), send nothing at all on a fresh profile, and compute `persistence` from a room played at `DEMO_TIMESCALE=6`, where "past the nudge threshold" meant 15 s.
- **Rungs may legally:** take `derived` as given (pure domain, no validation named), apply `90 s × (1 + 0.5 × persistence)` from `player-profile.md` with only the 60 s floor the companion names (no ceiling), treat `time_to_first_hint` as seconds, require `derived` on session start (422 without it), and key `mean_rung_per_lock_type` by lock type while the client sends one number.
- **Incompatibility:** `persistence = 1.8` gives a 171 s nudge threshold with no ceiling (the companion's "45 to 135 s" is an intent, not a rule); a millisecond value in a seconds field makes the median first-hint time 90 000; a fresh profile is a 422 on the first room the playtester opens; the demo recording pollutes the `PROFILE=demo` record that room 2's greeting must cite (CAP-6, "a real room-1 record"). And the web owner, having hand-written `Derived`, has violated the spirit of AD-2 without violating its letter.
- **Closing AD text (amend AD-8 and AD-2):** "`Derived` and `RoomResult` are pydantic models in `src/domain/schema.py`, so they appear in `GET /schema` and are generated for `web/` like every other type; `GET /schema` returns the JSON Schema of every model the HTTP API accepts or returns. `Derived` is `{sessions: int ≥ 0, persistence: float in [-1, 1], time_to_first_hint_s: float | null, mean_rung_per_lock_type: dict[LockType, float in [0, 3]]}`, with bounds enforced by pydantic validators (422 outside them) and `Derived.fresh()` (sessions 0, persistence 0, nulls) sent when no profile exists. The nudge threshold is `clamp(90 000 × (1 + 0.5 × persistence), 60 000, 135 000)` ms in `domain/rungs.py`, the only reader of `Derived`; `web/profile` is its only writer. The server computes `RoomResult` from the log at session end (`GET /sessions/{id}/result`), including `demo: DEMO_TIMESCALE > 1`; the client stores every result and excludes `demo` results when recomputing `Derived`."

### P-9 (medium) — Two selectors for one adapter: `MODE` and `GUIDE` both pick the `HintPhraser`

- **Units:** `src/infra` (adapter selection by `MODE`, AD-9) and `src/api/wiring.py` (reads `GUIDE=ollama|verbatim`, AD-14).
- **Infra may legally:** select `HintPhraser` by `MODE` as AD-9 lists it (`hosted` gives verbatim, `local` gives Ollama) and ignore `GUIDE`.
- **Wiring may legally:** select `HintPhraser` by `GUIDE`, since AD-14 defines the flag and nothing says `MODE` wins; `MODE=hosted GUIDE=ollama` (a copied `.env`) then wires the Ollama adapter on Modal, where it fails at the first hint (no Ollama), or, if someone installs it there, hosts the Guide that AD-5 exists to forbid.
- **Incompatibility:** whichever selection runs last wins silently; the cut-3 "verbatim rungs" path on the Mac is reachable by `GUIDE` but not by `MODE`, or the reverse; the privacy line in the README can be true of one wiring and false of the other.
- **Closing AD text (amend AD-9 and AD-14):** "`GUIDE` is the only selector of the `HintPhraser` adapter; `MODE` selects `JobStore`, `ArtifactStore`, `LedgerStore`, and `SessionStore` only. `GUIDE` defaults to `ollama` under `MODE=local` and `verbatim` under `MODE=hosted`; `Settings` fails at startup on `MODE=hosted` with `GUIDE=ollama`, and `GET /meta` reports the resolved `guide` value."

### P-10 (high) — Session state has no store, and a provider failure inside play has no shape

- **Units:** `src/api` (session routes) and `src/infra` with `src/providers`.
- **Api may legally:** keep sessions in a module-level dict: AD-7 forbids in-memory job state, AD-4 says "append-only log" without naming where, and AD-9's list of mode-selected adapters has no session store. On a `SpendCapExceeded` or `ProviderError` from a Trickster call mid-game, return the AD-13 envelope `{error: {code, message, stage}}` with `stage` set to the only thing it has (`"trickster"`).
- **Infra may legally:** provide exactly the adapters AD-9 lists and nothing for sessions. Providers may legally raise on the cap during play, as AD-6 requires.
- **Incompatibility:** with `max_inputs=20` and a container recycle (or any scale-out past twenty inputs), the judge's session vanishes mid-room with a 404; AD-8's "hosted sessions and their artifacts are deleted as a unit" has nothing enumerable to delete; the Tue Nov 10 purge cannot be written. Separately, the client's error handling is built for the build wizard (envelope with a pipeline stage); a cap refusal inside play surfaces as a stage error and halts the game, when the council's intent is a quiet "no proposal this window" and the video needs the game to continue.
- **Closing AD text (amend AD-9, AD-13, and the Structural Seed):** "A `SessionStore` port (`get`, `append_event`, `list_ids`, `delete`) sits in `pipeline/ports.py` beside `JobStore`, with the same local JSON and hosted `modal.Dict` adapters and selected by `MODE`; no session state lives in a process variable. `delete_session` removes the log and the room versions the session created, which is the AD-8 unit; a purge script `scripts/purge_hosted.py` lists and deletes them. Inside play, `SpendCapExceeded` and `ProviderError` from the Trickster are caught by the session route and recorded as a `trickster_card` with `accepted: false`, `edit_id: null`, and `reason: provider_unavailable`, never as an error envelope; the envelope is for build and session-creation routes and carries `stage: null` outside the pipeline." (Rubric review R-2, R-3 flag the hosted runner and session store; this pair gives the concrete failure and the port.)

## Smaller clashes seen while building the pairs

- The `validate → author` edge in the state diagram has no `regen += 1` and no record of which stage failed; `provenance.regeneration_count` (AD-16) is written by the stage runner from a counter that only `regenerate.py` increments; make `regenerate.py` the sole writer of the count and the stage runner the reader.
- `GET /meta` "exposes the active mode, flags" (AD-15): if it exposes `SPEND_CAP_USD` and the ledger total, the client can show a spend meter; if it exposes `X-Access-Code` semantics, it leaks. State the exact `Meta` model fields in `schema.py` (`mode`, `guide`, `demo_timescale`, `demo_trickster`, `cache`, `disclosure`, `retention`) and nothing else.
- `Interactable.instances` for grouped plurals: one hotspot or one polygon per instance? P-1 fixes the id; the `mask` field should be `polygons[]` (one per instance) so the client never has to split a multipolygon.

## What the pairs did not break

AD-1 (import boundaries), AD-3 (the `RoomView` boundary), AD-5 (the port surface), AD-11 (hotspot id equals interactable id), AD-15 (scripted source only), AD-16 (provenance), and AD-17 (one owner per package) held under every pair tried; two owners obeying them cannot build incompatible units on those axes. The holes are all in the seams between the pure domain and the two impure layers (client and adapters): time, identity, versions, counters, and payload shapes.
